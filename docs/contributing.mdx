## Required workflow

1. Branch from current `main`; never push directly to `main`.
2. Keep generic upstream sandbox/tool/SDK plumbing close to the pinned Strix release.
3. Put LyraShield model, budget, lifecycle, identity, evidence, and artifact behavior behind explicit reviewed boundaries in `lyrashield/**`.
4. Do not add another `strix/**` modification without a reviewed upstream-compatibility reason. The current hard allowlist contains only `strix/config/loader.py` and `strix/skills/__init__.py`. Preserve the LyraShield modification banner on those files.
5. Add tests and update `NOTICE`, `UPGRADES.md`, and operator docs when the contract changes.
6. Run `bash scripts/verify-controlled-derivative.sh` and `git diff --check`. The verify gate diffs `strix/**` against the pinned v1.5.3 base and fails on any path outside the two-file allowlist, more than 30 insertions, or any deletion. It also runs Ruff lint/format, the full `pytest` suite, headless mypy (excluding the upstream TUI), Bandit, package and binary smoke, sandbox smoke, and the public worker contract.
7. Require human approval and green Engine CI.

<Warning>
Do not add providers or models outside GPT-5.6 Terra and Luna; re-enable telemetry; weaken budget reservations; persist raw model output; or make confidence equivalent to verification.
</Warning>

Artifact schema changes require coordinated worker compatibility testing against `ecryptoguru/lyrashield-ai`.

## Security hardening

The engine includes a comprehensive security hardening pass (see the [Security hardening pass](https://github.com/ecryptoguru/lyrashield-engine/blob/main/UPGRADES.md#security-hardening-pass-2026-08-05) section in `UPGRADES.md` for the full audit and ledger). When contributing changes that touch security-sensitive areas:

- **Trust boundaries:** Do not remove or weaken `[SYSTEM-NOTICE]` or `[SYSTEM-VERIFIED PEER MESSAGE]` tags from the system prompt or message wrapping code.
- **Secret redaction:** Do not bypass `redact_text()` calls in `ReportState` or `maybe_compact`. PoC script code must always preserve internal paths for reproducibility.
- **Path redaction:** Do not remove the `_is_whitebox` mode-aware path redaction logic. Spill paths and tmp state must always be redacted.
- **Telemetry:** Do not hardcode telemetry keys. Use the lazy env var helpers. Do not spawn telemetry threads when `telemetry.enabled` is false.
- **Prompt sanitization:** Do not bypass `_sanitize_prompt_value`. The regex must cover `{{ }}`, `{% %}`, and `{# #}` Jinja tags.
- **Dedupe schema:** Do not remove `AgentOutputSchema(strict_json_schema=True)` from the dedupe model call.
