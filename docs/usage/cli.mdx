The production entry point is `lyrashield`, provided by the `lyrashield_adapter` package. The adapter forces telemetry off, disables the upstream self-update check, supports the authenticated `chatgpt/<model>` subscription route by default, and re-validates configuration after `--config` is applied. The bare upstream `strix` executable is not shipped in this distribution.

## Basic usage

```bash
uv run lyrashield (--target <target> | --target-list <path> | --mount <path>) [options]
```

Fresh runs require at least one target source: `--target`, `--target-list`, or `--mount`. `--resume` replaces the target source for a resumed run.

## Subcommands

### `provider-contract`

A bounded, target-free deployment gate. It sends no repository or scan data, caps each response at 64 output tokens, and prints only capability booleans plus safe error labels. Run it after a deployment change and before enabling an optional Responses feature.

```bash
uv run lyrashield provider-contract --require-programmatic-tool-calling
uv run lyrashield provider-contract --require-previous-response-id
```

Leave `LYRASHIELD_PROGRAMMATIC_TOOL_CALLING` unset unless the programmatic-tool-calling gate succeeds against the exact deployment. The default Azure path remains JSON function tools. A successful `--require-previous-response-id` probe does not authorize a future SQLite-to-server-state migration; the Agents SDK rejects `previous_response_id` when a session is supplied.

### `auth`

ChatGPT subscription sign-in helper. It exits without target, Docker, or scan setup. Authenticate with `lyrashield auth login chatgpt`, then configure the supported `chatgpt/<model>` main-model route. Set `LYRASHIELD_ALLOW_CHATGPT_SUBSCRIPTION=0` only when subscription auth must be disabled.

### `view`

Serves the prebuilt local viewer SPA. Source lives in `lyrashield/interface/viewer/frontend/`; built output is committed under `lyrashield/interface/viewer/static/`. End users never run a JS build.

## Options

<ParamField path="--target, -t" type="string">
  Target to test. Accepts URLs, repositories, local directories, domains, or IP addresses. Can be specified multiple times. The LyraShield production contract invokes the engine only for repository targets; URL targets are routed to the application's pinned deterministic URL scanner.
</ParamField>

<ParamField path="--target-list" type="string">
  Path to a file containing targets, one per non-empty, non-comment line. Lines starting with `#` are ignored. Can be specified multiple times and combined with `--target`.
</ParamField>

<ParamField path="--mount" type="string">
  Bind-mount a local directory into the sandbox (read-only) instead of copying it in file-by-file. Use this for large repositories that are too big to stream into the container. Can be specified multiple times.

  The engine copies local `--target` directories into the sandbox one file at a time, which stalls on very large trees. When a local target exceeds the copy limit (see `STRIX_MAX_LOCAL_COPY_MB` / `LYRASHIELD_MAX_LOCAL_COPY_MB`, default 1024 MB) the run exits early and asks you to re-run with `--mount`.

  <Note>
    The mount is read-only to protect your source from accidental modification. This is not a hard security boundary: a root process inside the container can remount it writable, so treat `--mount` as "scan my own code", not as isolation from untrusted code.
  </Note>

  <Note>
    The size pre-flight only covers local directory targets. Remote repositories (cloned at scan time) are not size-checked.
  </Note>
</ParamField>

<ParamField path="--instruction" type="string">
  Custom instructions for the scan. Use for credentials, focus areas, or specific testing approaches. Cannot be combined with `--instruction-file`. See [Custom Instructions](/usage/instructions) for the trust boundary.
</ParamField>

<ParamField path="--instruction-file" type="string">
  Path to a file containing detailed instructions. Cannot be combined with `--instruction`.
</ParamField>

<ParamField path="--scan-mode, -m" type="string" default="deep">
  Scan depth: `quick`, `standard`, or `deep`. The LyraShield application owns the user-facing preset, model route, and reasoning effort; see [Scan Modes](/usage/scan-modes).
</ParamField>

<ParamField path="--scope-mode" type="string" default="auto">
  Code scope mode: `auto` (enable PR diff-scope in CI/headless runs), `diff` (force changed-files scope), or `full` (disable diff-scope). Diff scope narrows repository context for suitable CI/headless work; it is a scope statement, not proof that unchanged code or deployed behavior is safe.
</ParamField>

<ParamField path="--diff-base" type="string">
  Target branch or commit to compare against (e.g., `origin/main`). Defaults to the repository's default branch.
</ParamField>

<ParamField path="--non-interactive, -n" type="boolean">
  Run in headless mode without TUI. Required for the production worker contract.
</ParamField>

<ParamField path="--config" type="string">
  Path to a custom config file (JSON) to use instead of `~/.strix/cli-config.json`. Configuration is re-validated after this file is applied because `LYRASHIELD_PRODUCT_BOUNDARY` is set by the adapter.
</ParamField>

<ParamField path="--max-budget, --max-budget-usd" type="number">
  Maximum LLM spend in USD for the whole scan, counted cumulatively across the root agent and every child agent. The budget is checked after each model response. Must be greater than `0`. Omit the flag for no limit.

  In non-interactive mode (`-n`), once the running cost reaches the threshold the scan stops cleanly with a `stopped` status (not a failure) and the sandbox is torn down. Sub-agents are stopped early, at 90% of the budget, reserving the final slice for the root agent to wind down and produce the final report.

  In interactive mode, reaching the budget pauses the scan instead of ending it: every agent parks, and sending any message resumes the scan with the cap extended by the original budget amount. There is no sub-agent reserve in interactive mode.

  As the budget is approached, graduated wrap-up warnings are surfaced to **every** agent so they can finish their work and call their lifecycle tool before the hard stop. The bands sit just below each role's own stop point: the root is warned at **70%, 85% and 95%** (it stops at 100%), while sub-agents are warned at **75%, 80% and 85%** (they stop at the 90% reserve). In interactive mode every agent uses the **70%, 85% and 95%** bands. Percentages shown in the warnings are the real cumulative spend against the full budget.

  Out-of-band metered calls (report deduplication) also reserve against this limit through `ReportUsageHooks.reserve_out_of_band_request`.

  **Limitations**

  - The check fires *after* a response is returned, so the final spend can slightly overshoot the limit by any calls already in flight when the threshold is crossed (most relevant with several child agents running concurrently).
  - Cost is a best-effort estimate derived from token usage and model pricing. Budget enforcement falls back to LiteLLM's `model_cost` table and then to conservative default rates for non-GPT-5.6 models, so validation does not crash if an internal path references an unlisted model. The LyraShield product entry point still rejects non-GPT-5.6 Terra/Luna deployments before scan start.
  - For LiteLLM-routed models, streaming success callbacks capture provider-reported cost. Message content remains excluded, but third-party LiteLLM callbacks configured in the same process can receive other streaming metadata such as model names, request IDs, and token counts.
</ParamField>

<ParamField path="--max-turns" type="integer" default="500">
  Maximum number of turns (one model response plus its tool round) allotted to **each** agent, applied per run. When an agent reaches this limit it is force-stopped.

  As the limit is approached, graduated wrap-up warnings (at 70%, 85% and 95%) are injected into that agent's next model turn so it can prioritise its remaining work and call its lifecycle tool (`finish_scan` for the root agent, `agent_finish` for sub-agents) before the hard stop. Must be greater than `0`.
</ParamField>

<ParamField path="--run-name" type="string">
  Stable run identifier supplied by an orchestrator. Combined with `--resume` it is an error.
</ParamField>

<ParamField path="--resume" type="string">
  Resume a prior scan by its run name (the dir under `./strix_runs/`). Picks up the root + every non-terminal subagent's full LLM history and agent topology. Skips fresh run-name generation. Cannot be combined with `--run-name` or any of `--target` / `--target-list` / `--mount` (the prior target list is reused).
</ParamField>

<ParamField path="--update" type="boolean">
  Disabled in LyraShield Engine. Self-update would fetch `usestrix/strix` release artifacts and replace this controlled derivative with the upstream distribution. Upgrade by installing a reviewed LyraShield Engine release instead.
</ParamField>

<ParamField path="--version, -v" type="boolean">
  Print the LyraShield Engine version and exit.
</ParamField>

## Examples

```bash
# Authorized repository scan (production-shaped invocation)
uv run lyrashield --target ./approved-repository --scan-mode quick --non-interactive --max-budget-usd 1.20

# Custom instructions (inline)
uv run lyrashield --target ./approved-repository --instruction "Focus on IDOR and auth bypass" --scan-mode quick -n

# Custom instructions (from file)
uv run lyrashield --target ./approved-repository --instruction-file ./instructions.txt -n

# Cap cost and per-agent turns
uv run lyrashield --target ./approved-repository -n --max-budget 25 --max-turns 300

# Force diff-scope against a specific base ref
uv run lyrashield -n --target ./ --scan-mode quick --scope-mode diff --diff-base origin/main

# Multi-target white-box testing (operator-only; production sends one repository target)
uv run lyrashield -t https://github.com/org/app -t https://staging.example.com

# Targets from a file
uv run lyrashield --target-list ./targets.txt

# Large local repository — bind-mount instead of copying it in
uv run lyrashield --mount ./huge-monorepo

# Resume a prior run
uv run lyrashield --resume prior-run-name -n
```

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | Scan completed successfully (interactive mode always exits `0`; in headless mode, `0` means no vulnerabilities were found) |
| 1 | A fatal error occurred before or during the scan (e.g. missing environment variables, Docker unavailable, invalid config file, diff-scope resolution failure, or an unhandled error) |
| 2 | Vulnerabilities found (headless mode only) |

The TypeScript worker treats all engine output as untrusted and schema-validates the bounded artifacts; exit codes are implementation signals, not verification proof.
