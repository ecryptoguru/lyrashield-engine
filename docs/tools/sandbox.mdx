The engine uses an upstream-derived Kali Linux-based Docker sandbox with security tools available through the [terminal](/tools/terminal).

<Warning>
The checked-in list describes the upstream sandbox capability surface. Production must pin and inspect the actual image digest; documentation alone does not prove a tool version, execution, coverage, or isolation property.

The build creates a fresh internal EC certificate authority for each image, so two clean builds of the same source are not expected to be byte-for-byte identical. The release workflow therefore qualifies one pushed candidate digest, smokes that exact digest on both supported architectures, and promotes the same manifest without rebuilding it. Reproducibility here means pinned source inputs plus immutable tested-artifact continuity, not independently regenerated digest equality.

</Warning>

## Security and provenance

The engine does not add `NET_ADMIN` or `NET_RAW` to sandbox containers by default. Set `STRIX_SANDBOX_ENABLE_NETWORK_CAPABILITIES=1` only for authorized workflows that require advanced raw-socket operations such as SYN scans. The legacy disable variable remains supported for compatibility.

Sandbox containers run with **default-on resource caps** (`mem_limit=2g`, `shm_size=512m`, `cpus=2`, `pids_limit=512`): an autonomous agent executes model-generated, attacker-influenced commands inside the container, so a fork bomb or memory hog must not be able to exhaust the host and take down co-located scans. Set any cap variable to `0`/`off`/`none`/`unlimited` to restore docker's unbounded default for that knob; any other value overrides the default. An unparseable value falls back to the default, never to unbounded. The effective resolved cap set is logged at container create (`sandbox caps: mem=… cpus=… pids=…`).

| Variable                                     | Default             | Effect                                                                                                                                                                                                                       |
| -------------------------------------------- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `STRIX_SANDBOX_MEM_LIMIT`                    | `2g`                | Container memory cap. Opt-out token restores docker's unbounded default.                                                                                                                                                    |
| `STRIX_SANDBOX_SHM_SIZE`                     | `512m`              | `/dev/shm` size (docker's 64m default OOMs Chromium/headless tools).                                                                                                                                                          |
| `STRIX_SANDBOX_CPUS`                         | `2`                 | CPU quota as a float (applied as `nano_cpus`).                                                                                                                                                                                |
| `STRIX_SANDBOX_PIDS_LIMIT`                   | `512`               | Process-count cap (fork-bomb bound).                                                                                                                                                                                          |
| `STRIX_SANDBOX_ENABLE_NETWORK_CAPABILITIES`  | unset               | Set to `1`/`true`/`yes` to add `NET_ADMIN`/`NET_RAW`; otherwise both remain omitted.                                                                                                                                         |
| `STRIX_SANDBOX_DISABLE_NETWORK_CAPABILITIES` | unset               | Legacy compatibility switch. It is consulted only when the enable variable is unset.                                                                                                                                         |
| `STRIX_IMAGE_DIGEST`                         | unset               | Optional 64-character SHA-256 digest to verify after `pull_docker_image` completes (for example, `sha256:abc123…`). If the local image digest does not contain this value, the image is re-pulled before verification fails. |
| `LYRASHIELD_IMAGE`                           | `strix-sandbox:dev` | Image reference. Production must use the immutable `ghcr.io/ecryptoguru/lyrashield-sandbox@sha256:…` digest emitted by the verified release workflow, not an upstream image or a tag.                                        |

`STRIX_SANDBOX_ALLOW_HOST_GATEWAY` remains opt-in; do not enable it unless an explicitly authorized local workflow requires `host.docker.internal` access.

Production workers use an isolated remote Docker endpoint (`ssh://` or TLS-protected `tcp://`), never a shared host Docker socket. The sandbox release workflow runs non-root `nmap` and Caido smoke checks for each supported architecture before it publishes the image digest, SPDX SBOM, and signed provenance attestation. A separate application release verifies the worker image digest built with this engine; the dedicated VM receives that worker only through an explicit digest promotion and reconciliation, never through a mutable tag.
