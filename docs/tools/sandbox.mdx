The engine uses an upstream-derived Kali Linux-based Docker sandbox with security tools available through the [terminal](/tools/terminal).

<Warning>
The checked-in list describes the upstream sandbox capability surface. Production must pin and inspect the actual image digest; documentation alone does not prove a tool version, execution, coverage, or isolation property.
</Warning>

## Security and provenance

The engine does not add `NET_ADMIN` or `NET_RAW` to sandbox containers by default. Set `STRIX_SANDBOX_ENABLE_NETWORK_CAPABILITIES=1` only for authorized workflows that require advanced raw-socket operations such as SYN scans. The legacy disable variable remains supported for compatibility.

| Variable | Default | Effect |
| --- | --- | --- |
| `STRIX_SANDBOX_ENABLE_NETWORK_CAPABILITIES` | unset | Set to `1`/`true`/`yes` to add `NET_ADMIN`/`NET_RAW`; otherwise both remain omitted. |
| `STRIX_SANDBOX_DISABLE_NETWORK_CAPABILITIES` | unset | Legacy compatibility switch. It is consulted only when the enable variable is unset. |
| `STRIX_IMAGE_DIGEST` | unset | Optional 64-character SHA-256 digest to verify after `pull_docker_image` completes (for example, `sha256:abc123…`). If the local image digest does not contain this value, the image is re-pulled before verification fails. |
| `LYRASHIELD_IMAGE` | `strix-sandbox:dev` | Image reference. Production must use the immutable `ghcr.io/ecryptoguru/lyrashield-sandbox@sha256:…` digest emitted by the verified release workflow, not an upstream image or a tag. |

`STRIX_SANDBOX_ALLOW_HOST_GATEWAY` remains opt-in; do not enable it unless an explicitly authorized local workflow requires `host.docker.internal` access.

Production workers use an isolated remote Docker endpoint (`ssh://` or TLS-protected `tcp://`), never a shared host Docker socket. The sandbox release workflow runs non-root `nmap` and Caido smoke checks for each supported architecture before it publishes the image digest, SPDX SBOM, and signed provenance attestation.
