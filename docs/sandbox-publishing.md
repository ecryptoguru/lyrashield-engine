# Publishing the sandbox image

The sandbox publisher builds one image on each native GitHub-hosted platform, rather than emulating ARM on the x86 runner. Each image must pass the existing sandbox smoke and Go application audits before it can contribute a digest. The final job assembles the two qualified digests, verifies the exact runnable child manifests, creates the SBOM and attestations, and only then moves the release tags. The final digest, not a tag, is the deployable reference.

A manual dispatch from `main` may select an optional **full 40-character engine commit** with `engine_revision`; leaving it empty selects the workflow commit. The only historical revision currently approved for explicit selection is `992b3d9df696753c7b62a31ea58f1ca5d21055c1`; adding another requires a reviewed workflow change and its own qualification. A `sandbox-v*` tag builds its own commit. The selected engine commit must be an ancestor of the dispatch/tag commit and have a successful, completed `Engine CI` push run on `main`. Both native jobs check out that exact revision and record it as the image revision label. Dispatching this newer workflow for the approved earlier engine revision does not change the engine source revision.

The normal GitHub provenance attestation identifies the **workflow revision**. A separate signed `https://lyrashieldai.com/attestations/sandbox-qualification/v1` predicate binds the selected engine revision, workflow revision, successful engine CI run, GitHub run and attempt, both platform index and runnable manifest digests, and the assembled index digest. A consumer that accepts a historical engine revision must verify both attestations, the trusted signer and certificate run/attempt, the predicate's values and final subject, the exact reviewed workflow revision, and the successful native jobs for that same run. An image label or a caller-supplied predicate alone is not evidence of source or qualification.

A failed, cancelled or timed-out build leaves only uniquely named candidate artifacts; it does not qualify or promote a digest. An actual publish is qualified only when the complete workflow, both native jobs, index checks, audits and attestations have succeeded and the digest has been independently verified.
