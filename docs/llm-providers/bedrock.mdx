---
title: "AWS Bedrock"
description: "GPT-5.6 Terra and Luna through Bedrock Mantle only"
---

<Warning>
Standard AWS Bedrock routes are not supported by LyraShield Engine. The only
supported Bedrock provider is `bedrock_mantle`, and its route must identify an
approved GPT-5.6 Terra or Luna deployment. All other Bedrock models and provider
markers remain outside the LyraShield production contract.
</Warning>

Example:

```bash
export LYRASHIELD_LLM="bedrock_mantle/openai.gpt-5.6-luna"
export BEDROCK_MANTLE_API_KEY="<short-lived-bearer-token>"
export BEDROCK_MANTLE_REGION="us-east-1"
```

Supported Bearer configuration is `BEDROCK_MANTLE_API_KEY` (or
`AWS_BEARER_TOKEN_BEDROCK`), optional `BEDROCK_MANTLE_API_BASE`, and region
`BEDROCK_MANTLE_REGION`, `AWS_REGION_NAME`, or `AWS_REGION`. Without a
Bearer token, the pinned provider uses the standard AWS credential chain,
including IAM roles, web identity, profiles, or
`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` with an optional
`AWS_SESSION_TOKEN`. `OPENAI_API_KEY` and `OPENAI_BASE_URL` are not
Bedrock Mantle credentials.

Do not use the `bedrock` provider marker. The local subprocess inherits its
parent environment, so run it from a secret-minimized shell and expose only the
approved deployment credentials. Hosted workers must use their existing
allowlisted runtime environment.
