title: "Configuration"
description: "Environment variables and config file for LyraShield Engine"
---

Configure LyraShield Engine with environment variables or a JSON config file. The `lyrashield` entry point (`lyrashield_adapter`) accepts `LYRASHIELD_*` aliases for every `STRIX_*` setting; either form works, but `LYRASHIELD_*` is the preferred product spelling. The adapter also forces `STRIX_TELEMETRY=0`, sets `STRIX_NO_UPDATE_CHECK=1`, sets `LYRASHIELD_PRODUCT_BOUNDARY=1`, and admits GPT-6 Sol or Luna deployments from OpenAI or Azure/Azure AI.

<Warning>
Only approved GPT-6 Sol or Luna deployments are accepted as scan routes. The current allow-list is OpenAI, Azure/Azure AI, and the authenticated `chatgpt/` subscription route. Deduplication uses the main model when `LYRASHIELD_DEDUPE_MODEL` is unset, so it can also use the main ChatGPT subscription route; an explicit delegate or dedicated dedupe model override must use a metered OpenAI or Azure/Azure AI route. `LYRASHIELD_ALLOW_CHATGPT_SUBSCRIPTION` defaults to enabled for the standalone engine and can be set to `0` to refuse subscription routes outright; the production worker disables it. Older GPT-5 deployments and other provider markers (OpenRouter, Bedrock, Vertex, Novita, local) are not admitted to new scans.

Parallel Search may be used as an optional `web_search` tool when explicitly enabled with `LYRASHIELD_WEB_SEARCH_ENABLED=1` and `PARALLEL_API_KEY` or `LYRASHIELD_WEB_SEARCH_API_KEY`. It is not a model route and never replaces the GPT-6 main model.

</Warning>

## LLM configuration

<ParamField path="LYRASHIELD_LLM" type="string" required>
  Primary model in LiteLLM format. Metered `openai`, `azure`, and `azure_ai`
  routes must identify a GPT-6 Sol or Luna deployment (for example
  `openai/gpt-6-luna` or `azure_ai/gpt-6-sol`). Alias of `STRIX_LLM`.
</ParamField>

<ParamField path="LYRASHIELD_DELEGATE_LLM" type="string">
  Bounded specialist tier model for Deep scans. The Sol/medium root owns
  coordination and cross-file judgment; Luna/high child specialists handle
  focused tasks. Must identify a GPT-6 Luna deployment. Alias of
  `STRIX_DELEGATE_LLM`.
</ParamField>

<ParamField path="LLM_API_KEY" type="string">
  API key for the LLM provider. Also accepted: `OPENAI_API_KEY`,
  `AZURE_OPENAI_API_KEY`, `AZURE_AI_API_KEY`. Not required when the approved
  endpoint supplies authentication by another controlled mechanism.
</ParamField>

<ParamField path="LLM_API_BASE" type="string">

  `LITELLM_BASE_URL`, `OLLAMA_API_BASE`, `AZURE_OPENAI_ENDPOINT`,
  `AZURE_OPENAI_API_BASE`, `AZURE_AI_API_BASE`. Azure AI Foundry endpoints are
  normalized to their `/openai/v1/` base.
</ParamField>

<ParamField path="LLM_API_MODE" default="auto" type="string">
  API selection policy: `auto`, `responses`, or `chat_completions`. Automatic
  selection uses the admitted GPT-6 model capability and selects Responses,
  including when `LLM_API_BASE` points to a custom gateway. Set an explicit
  policy when the approved gateway requires one API. Root, delegate, and
  fallback routes share this policy. Alias: `LYRASHIELD_LLM_API_MODE`.
</ParamField>

<ParamField path="LLM_API_VERSION" type="string">
  Azure API version. Also accepted: `AZURE_API_VERSION`,
  `AZURE_OPENAI_API_VERSION`.
</ParamField>

<ParamField path="LYRASHIELD_ALLOW_CHATGPT_SUBSCRIPTION" default="true" type="boolean">
  Controls `chatgpt/gpt-6-*` subscription-backed scans for the main model. Enabled by default; set to `0`/`false`/`no` to disable. When enabled, `lyrashield auth login chatgpt` is available and the scan is recorded with `auth_mode: "subscription"` and `llm_usage.cost: 0` (ancillary charges such as paid web search remain metered). Also accepted: `STRIX_ALLOW_CHATGPT_SUBSCRIPTION`.
</ParamField>

<ParamField path="LLM_EXTRA_HEADERS" type="string">
  Extra HTTP headers sent on every LLM request, as a JSON object (e.g. `{"X-Feature-Key":"value","X-Tenant":"acme"}`). Useful for OpenAI-compatible gateways that require attribution or routing headers in addition to the bearer token. The bearer token still comes from `LLM_API_KEY`. Alias: `LYRASHIELD_EXTRA_HEADERS`. Applies to both the LiteLLM and native OpenAI routing paths.
</ParamField>

<ParamField path="LLM_TIMEOUT" default="300" type="integer">
  Request timeout in seconds for LLM calls. Alias: `LYRASHIELD_LLM_TIMEOUT`.
  Startup preflight has a separate 30-second total allowance, bounded by this

</ParamField>

<ParamField path="LYRASHIELD_REASONING_EFFORT" default="medium" type="string">

  `low`, `medium`, `high`, `xhigh`, `max`. The application worker owns reasoning
  selection in production; use this only for operator-controlled local
  execution. Alias of `STRIX_REASONING_EFFORT`.
</ParamField>

<ParamField
  path="LYRASHIELD_DELEGATE_REASONING_EFFORT"
  default="medium"
  type="string"
>
  Reasoning effort for the bounded specialist tier. Same valid values as above.
  Alias of `STRIX_DELEGATE_REASONING_EFFORT`.
</ParamField>

<ParamField path="LYRASHIELD_PROMPT_CACHE" default="true" type="boolean">
  Enable implicit prompt caching. Defaults to on. Alias of `STRIX_PROMPT_CACHE`.
</ParamField>

<ParamField path="LYRASHIELD_PROMPT_CACHE_EXPLICIT" default="false" type="boolean">
  Enable GPT-6 explicit cache breakpoints for prompt-cache reads and writes.
  This is opt-in and requires a provider smoke scan for the exact deployment;
  unsupported routes ignore it. Usage artifacts separately record cache-read
  and cache-write tokens when the provider reports them.
</ParamField>

<ParamField path="LYRASHIELD_PROMPT_CACHE_ROUTING" default="false" type="boolean">
  Emit stable, scan-isolated GPT-6 `prompt_cache_key` routing keys for the coordinator,
  delegate and fallback prompt families. The standalone engine default is off.
  The LyraShield product worker turns it on by default for the admitted GPT-6
  deployments and an operator can set `LYRASHIELD_PROMPT_CACHE_ROUTING=0` to
  turn it off. It is independent of explicit breakpoints and does not turn
  caching on when `LYRASHIELD_PROMPT_CACHE=false`. Enable it for a GPT-6
  deployment only after a provider smoke scan confirms that deployment honors
  the key.
</ParamField>

### Offline cache-economics evaluator

Run `python -m lyrashield.evals.cache_economics path/to/run.json` to produce a
read-only, allowlisted accounting summary from provider request receipts. The
evaluator makes no provider or target calls. It reports no cost or scenarios
when request entries and declared usage totals do not reconcile. Optional
`--input-reduction FRACTION` and `--cache-conversion FRACTION` outputs are
hypothetical repricings of complete receipts, not measured savings.

<ParamField path="LLM_DISABLE_STREAMING" default="false" type="boolean">
  Disable streaming on LLM calls. Alias: `LYRASHIELD_DISABLE_STREAMING`.
</ParamField>

<ParamField
  path="LYRASHIELD_FORCE_REQUIRED_TOOL_CHOICE"
  default="false"
  type="boolean"
>
  Force required tool choice on model requests. Alias of
  `STRIX_FORCE_REQUIRED_TOOL_CHOICE`.
</ParamField>

<ParamField path="LYRASHIELD_MAX_OUTPUT_TOKENS" type="integer">
  Hard cap on tokens generated per request. Unset keeps the per-scan-mode
  default chosen by the runner; when set it replaces that default for every
  agent (delegates stay separately clamped). Also tightens the pre-request
  budget reservation. Alias of `STRIX_MAX_OUTPUT_TOKENS`.
</ParamField>

<ParamField path="LYRASHIELD_MAX_INPUT_TOKENS" type="integer">
  Ceiling that history compaction keeps a request's input under. This is not a
  hard reject: exceeding it compacts older history rather than failing the
  request. Clamped below the GPT-6 long-context boundary, above which input is
  billed at 2x — the clamp is what stops this knob from raising cost. Alias of
  `STRIX_MAX_INPUT_TOKENS`.
</ParamField>

### Local request diagnostics

<ParamField path="LYRASHIELD_REQUEST_DIAGNOSTICS" default="false" type="boolean">
  Opt in to a separate local `.state/request-diagnostics.json` file inside the run
  directory. It retains at most 256 SDK model-call attempt records and 128 KiB, evicts
  the oldest records, and reports a bounded `dropped` count. Writes are serialized
  within the scan process and atomically replace a file with owner-only permissions.
</ParamField>

Records contain only available provider request/response IDs, the configured
model and selected route, a terminal outcome, a fixed retry-reason classification,
duration, observed time to first token, and token buckets. IDs and strings are
limited to 128 characters and sensitive values are omitted. Headers, prompts,
response text, raw errors, and request bodies are excluded. No diagnostics are
sent to a telemetry service or added to the customer evidence artifacts.

Time to first token is recorded only when a streamed token delta is observed;
it is unavailable for the non-streaming fallback. Request IDs are omitted when
the SDK adapter does not expose them. Retry reasons classify failures and do not
assert that a retry occurred; SDK-internal HTTP retries are not logged separately.
Diagnostics issue no requests or retries of their
own and preserve cancellation. A process terminated before its attempt finishes
may have no record for that attempt. Persistence failures do not change scan
behavior.

### Programmatic tool calling (opt-in gate)

<ParamField path="LYRASHIELD_PROGRAMMATIC_TOOL_CALLING" type="string">
  Leave unset unless the capability gate succeeds against the exact deployment.
  The configured Azure AI Foundry GPT-6 endpoint supports baseline Responses
  requests and `previous_response_id`, but rejects the Responses
  `programmatic_tool_calling` tool type. Use direct JSON function tools in
  production. Set to `1` only after `uv run lyrashield provider-contract
  --require-programmatic-tool-calling` passes; set to `0` to force it off.
</ParamField>

## Dedicated deduplication model

Finding deduplication is a cheap, structured classification task. By default it runs on the main model, but you can route it to a smaller/cheaper model without affecting the agents that do the actual testing.

<ParamField path="LYRASHIELD_DEDUPE_MODEL" type="string">
  Optional model override used to judge whether a candidate finding duplicates
  an existing report. When unset, deduplication uses `LYRASHIELD_LLM`, including
  an authenticated ChatGPT subscription route. An explicit override must use a
  metered OpenAI or Azure/Azure AI GPT-6 route. The legacy environment alias
  is also supported.
</ParamField>

<ParamField path="DEDUPE_LLM_API_KEY" type="string">
  Optional provider key for the deduplication model.
</ParamField>

<ParamField path="DEDUPE_LLM_API_BASE" type="string">
  Optional custom API base URL for the deduplication model. Use when the dedupe
  model runs on a different endpoint than the main model.
</ParamField>

<ParamField path="DEDUPE_LLM_API_MODE" default="auto" type="string">
  Dedicated dedupe API policy: `auto`, `responses`, or `chat_completions`.
  Automatic selection uses Responses for admitted GPT-6 models independently
  of the dedupe endpoint URL. When no dedicated dedupe model is configured,
  the main model's API policy applies. Alias: `LYRASHIELD_DEDUPE_LLM_API_MODE`.
</ParamField>

<ParamField path="DEDUPE_LLM_EXTRA_HEADERS" type="string">
  Optional JSON object of extra HTTP headers sent on every deduplication-model request, e.g. `{"X-Feature-Key":"value"}`. A dedicated model reuses `LLM_EXTRA_HEADERS` only when it uses the same provider and normalized API endpoint as the main model (scheme, authority, path, query and fragment; a trailing path slash is ignored). A different dedicated endpoint never inherits the main model's headers; set this when that endpoint needs custom headers.
</ParamField>

<ParamField path="LYRASHIELD_DEDUPE_REASONING_EFFORT" type="string">
  Reasoning effort for the deduplication model. Defaults to the model's own
  baseline when unset. Same valid values as `LYRASHIELD_REASONING_EFFORT`. Alias
  of `STRIX_DEDUPE_REASONING_EFFORT`.
</ParamField>

## Specialist turn guidance

<ParamField path="LYRASHIELD_SUBAGENT_TURN_LIMITS" type="JSON object" default="{}">
  Optional advisory turn targets keyed by canonical `category/skill` identifiers.
  For example: `'{"vulnerabilities/xss":30,"vulnerabilities/sql_injection":60}'`.
  Values must be positive integers at most 10,000; names must be category-qualified,
  and at most 128 entries are accepted. Unknown or unselected skills have no effect.
</ParamField>

The largest target among a child's selected skills applies and is clamped to the
existing hard `--max-turns` ceiling. It is recomputed for fresh and restored
specialists. Trusted notices advise wrap-up ten turns before the target (or on
the first turn for smaller targets), at the target, and every five turns past it.
The guidance never stops a specialist, increases a hard limit, launches an
additional request, or grants more scope, budget, runtime, or agent capacity.
The root agent receives no specialist target.

`docker network inspect "$STRIX_DOCKER_SANDBOX_NETWORK"`, remove the old network
with `docker network rm "$STRIX_DOCKER_SANDBOX_NETWORK"`, then rerun the
provisioning script. Network removal is an operator-controlled downtime step;
the script never disconnects or deletes a network that may still be in use.

### Sandbox capabilities and image pinning

The engine omits `NET_ADMIN` and `NET_RAW` by default. Add them only for authorized workflows that require advanced raw-socket operations such as SYN scans.

Sandbox resource caps are **default-on** (`mem_limit=2g`, `shm_size=512m`, `cpus=2`, `pids_limit=512`) so an autonomous agent cannot exhaust the host. Set a cap variable to `0`/`off`/`none`/`unlimited` to restore docker's unbounded default for that knob; any other value overrides the default, and an unparseable value falls back to the default. The resolved cap set is logged at container create.

| Variable                                     | Default | Effect                                                                                                                                                                                                                       |
| -------------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `STRIX_SANDBOX_MEM_LIMIT`                    | `2g`    | Container memory cap. Opt-out token restores docker's unbounded default.                                                                                                                                                    |
| `STRIX_SANDBOX_SHM_SIZE`                     | `512m`  | `/dev/shm` size (docker's 64m default OOMs Chromium/headless tools).                                                                                                                                                          |
| `STRIX_SANDBOX_CPUS`                         | `2`     | CPU quota as a float (applied as `nano_cpus`).                                                                                                                                                                                |
| `STRIX_SANDBOX_PIDS_LIMIT`                   | `512`   | Process-count cap (fork-bomb bound).                                                                                                                                                                                          |
| `STRIX_SANDBOX_ENABLE_NETWORK_CAPABILITIES`  | unset   | Set to `1`/`true`/`yes` to add `NET_ADMIN`/`NET_RAW`; otherwise both remain omitted.                                                                                                                                         |
| `STRIX_SANDBOX_DISABLE_NETWORK_CAPABILITIES` | unset   | Legacy compatibility switch. It is consulted only when the enable variable is unset.                                                                                                                                         |
| `STRIX_IMAGE_DIGEST`                         | unset   | Optional 64-character SHA-256 digest to verify after `pull_docker_image` completes (for example, `sha256:abc123…`). If the local image digest does not contain this value, the image is re-pulled before verification fails. |
| `STRIX_SANDBOX_ALLOW_HOST_GATEWAY`           | unset   | Opt-in `host.docker.internal` access. Do not enable unless an explicitly authorized local workflow requires it.                                                                                                              |

The `publish-sandbox` workflow pushes one multi-architecture candidate, runs the non-root capability smoke tests against that exact digest on both supported architectures, and only then promotes the same digest to release tags. It emits an SPDX SBOM plus signed provenance/SBOM attestations for that digest. Promote the digest, never a tag, as one release unit with its worker configuration. The application repository separately verifies and publishes the worker image digest; an operator promotes that worker digest explicitly on the dedicated VM, then reconciles its running reference, OCI labels, health, and scan readiness. Neither image follows a mutable tag in production.

## Evidence artifacts and pending HTTP claims

<ParamField path="LYRASHIELD_RUN_RECORD_V1_1" default="false" type="boolean">
  Enable the versioned evidence artifact family for new runs: finding evidence
  metadata, coverage and threat-model artifacts, HTTP export and the result
  manifest. Existing runs retain the schema version they started with.
</ParamField>

<ParamField path="LYRASHIELD_PENDING_HTTP_EVIDENCE" default="false" type="boolean">
  When enabled together with `LYRASHIELD_RUN_RECORD_V1_1`, new runs use
  `run.json` schema `1.2` and finding `evidence_contract_version: "1.2"`.
  The companion artifact family remains `evidence_format: "1.1"`.
  Enable this writer only after compatible readers are deployed and qualified.
</ParamField>

In schema 1.2, submitted proxy request IDs begin in
`pending_http_exchange_ids`, including when a live lookup finds the ID.
Pending claims and `http_exchange_ids` each allow up to 10 distinct numeric
ASCII IDs of at most 128 characters. Pending IDs are correlation claims;
they do not create verification receipts, change deduplication identity or
prove a vulnerability.

Before sandbox teardown, the engine exports captured HTTP evidence and
reconciles eligible references. Promotion requires matching run identity,
finding revision and report-artifact revision, the actual captured request,
and a valid result manifest covering both `vulnerabilities.json` and
`http_exchanges.json`. The captured request must have a SHA-256 digest and a
host matching the finding's absolute target or endpoint URL. Exported
references describe captured evidence; they do not upgrade the finding's
vulnerability verification state.

Missing, foreign, timed-out and omitted references stay pending and are
reported as unavailable evidence. A partial export promotes only its valid
subset. Each finding's export binding selects existing verified references
first, followed by pending claims, up to 10 IDs; overflow stays pending and
is recorded as `capacity_omitted_request_ids`. Previously validated durable
captures may survive a later proxy outage when their manifest and revision
bindings still validate; `reused_durable_exchanges` records that reuse.

The engine stages an export before committing finding projections and
writing `run.json` last. Caught write failures restore the prior artifacts
and memory. An interrupted multi-file replacement is detected by manifest
verification and fails closed on resume or ingest; the protocol is not a
filesystem-wide crash-atomic transaction.

Offline reuse requires the original receipt's exact manifest entries for both
finding and HTTP files. The engine does not reconstruct a missing assertion
by hashing whichever files happen to be present. Unchanged claim submissions
do not consume finding revisions; changing authored finding content makes
its previous capture binding stale and returns those references to pending.

If demotion would exceed the 10 pending-ID limit, reconciliation records
`evidence_export.status: "failed"` with `reason: "pending_capacity_exceeded"`
and preserves both original claim arrays and their artifacts. Retained
ordinary IDs in this failed result are unavailable evidence. Restore proxy
access to reconcile the retained claims, or explicitly replace the claim set
with the references that should remain; the engine does not silently discard
claims or increase the authorized budget. Shared IDs selected by another
finding are not reported as globally capacity-omitted.

Fresh and reused HTTP exports must fit the complete 1 MiB serialized budget.
Header counts and names are bounded, body samples may be removed, and any
omitted captures remain explicit. An export that cannot fit is unavailable.
Export work has a 20-second total allowance; sandbox cleanup has a separate
20-second allowance and still runs when export is cancelled or times out.

For development and consumer-contract qualification, run the synthetic fixture
generator from the repository root using the project's Python environment:

```bash
PYTHONPATH=. .venv/bin/python scripts/generate-http-evidence-fixtures.py \
  --output-dir "$HTTP_EVIDENCE_FIXTURES"
```

Set `HTTP_EVIDENCE_FIXTURES` to a new, nonexistent output directory under an
existing parent outside the source checkout. The generator uses the engine's
installed dependencies and standard library; it does not require test-only Python packages or live provider/proxy
access. It is a development harness, not an installed runtime command. It
exclusively creates a private directory and refuses existing output paths,
including symlinks. Files are published without following or replacing links;
`summary.json` records exact hashes, byte lengths and expected claim arrays. If generation fails, inspect
the private partial output and choose a fresh directory for another run.
Generated cases exercise partial capture, durable reuse, capacity, explicit
unavailable evidence,
serialized-size limits and late results after cancellation. Reader validation
must use the raw bytes without reformatting them.

Disabling either flag does not remove support for persisted schema-1.2 runs.
Resumed schema-1.0 and schema-1.1 runs keep their existing version and do not
start emitting pending fields. Pending evidence and unresolved coverage
remain explicit limitations; follow-up work stays within the authorized
scan budget.

## Viewer

<ParamField
  path="LYRASHIELD_APP_URL"
  default=""
  type="string"

## Config file

The engine stores configuration in `~/.strix/cli-config.json`. Specify a custom config file with `--config`:

```bash
uv run lyrashield --target ./app --config /path/to/config.json
```

Configuration is re-validated after the config file is applied because `LYRASHIELD_PRODUCT_BOUNDARY` is set by the adapter — a `--config` that swaps in an unsupported model is rejected.

**Config file format:**

```json
{
  "env": {
    "LYRASHIELD_LLM": "openai/gpt-6-luna",
    "LLM_API_KEY": "sk-...",
    "LYRASHIELD_REASONING_EFFORT": "medium"
  }
}
```

## Example setup

```bash
# Required: approved GPT-6 Sol or Luna deployment
export LYRASHIELD_LLM="openai/gpt-6-luna"
export LLM_API_KEY="<credential>"
export LLM_API_BASE="https://<approved-endpoint>"

# Optional: Deep scans use Sol to coordinate, Luna for focused specialists
export LYRASHIELD_DELEGATE_LLM="openai/gpt-6-luna"

# Optional: operator-controlled local execution only (worker owns this in production)
export LYRASHIELD_REASONING_EFFORT="medium"

# Optional: token caps (see field docs above for behavior)
export LYRASHIELD_MAX_OUTPUT_TOKENS=4096
export LYRASHIELD_MAX_INPUT_TOKENS=64000

# Optional: ChatGPT subscription-backed main model (requires `lyrashield auth login chatgpt` first)
# export LYRASHIELD_LLM="chatgpt/gpt-6-luna"

# export LYRASHIELD_ALLOW_CHATGPT_SUBSCRIPTION=0  # to explicitly disable subscription auth

# Optional: custom timeouts / extra headers
export LLM_TIMEOUT="600"
export LLM_EXTRA_HEADERS='{"X-Tenant":"acme"}'
```


## Interactive budget controls

An interactive scan that reaches `--max-budget-usd` pauses its agents. Messages
sent during that pause are queued; sending a message does not restart the scan
or authorize additional spend.

Use **Increase budget** in the local browser viewer, or type `/increase-budget`
in the TUI, to add the original configured budget amount once. For example, a
scan started with `--max-budget-usd 1.20` increases its limit from $1.20 to $2.40.
The interfaces show the increment and current limit before increasing it. The
scan remains paused after an increase. Then use **Resume scan** or `/resume` to
restart paused agents. An exhausted limit rejects resume and asks for an explicit
increase first. Non-interactive scans keep their hard budget ceiling, and these
controls cannot revive a stopped scan.

The viewer can steer only the run that launched it. Past runs, including
incomplete past runs, remain read-only. A **Queued** acknowledgement confirms
mailbox acceptance, not execution or completion. **Delivery unknown** means the
acknowledgement was lost or timed out: retry the unchanged draft or same control
to check acceptance without duplicating it. Rejected and unknown messages keep
the draft. Submission IDs are retained for the current process; after 4,096
unique submissions, further new submissions are rejected to bound memory use.
