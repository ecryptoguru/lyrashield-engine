# Offline OCI layer reconstruction prototype

`scripts/reconstruct_oci_layers.py` is an **unwired in-memory experiment**, not a release gate or a qualified container runtime. `reconstruct_verified(directory_fd, manifest_digest, platform)` uses the existing byte-binding verifier, buffers each layer from the same stream being hashed, and applies it only after the compressed descriptor and uncompressed DiffID verify. It returns the virtual tree only after every layer succeeds. The caller must independently authenticate the expected manifest/platform; this code does not verify an index, signature, workflow, SPDX or package coverage. It does not write, extract, or execute image content on the host.

The virtual tree holds content and the supported tar metadata for files and directories. Symlink targets, including bounded absolute forms and targets containing `..`, are retained verbatim as data and are never followed. Absolute symlink targets are interpreted only as image-namespace text; this prototype never resolves them on the host or asserts their eventual referents. Hardlinks to already-existing regular files share the same immutable node, so replacing the original path does not change an earlier alias. Hardlink self-references and hardlink headers whose mode, uid, gid or mtime differ from the target are rejected: extraction implementations may apply those attributes to the shared inode differently. Paths must have explicit existing directory parents; forward hardlinks, links to directories or symlinks, absolute or traversing hardlink targets, ambiguous link spellings, symlink ancestors, duplicate normalized paths, special files, global or stacked PAX headers, GNU extensions and sparse entries fail closed. A local PAX header is limited to 16 KiB and may contain only distinct nonempty UTF-8 `path` and `linkpath` overrides; controls, unsafe paths, invalid link overrides and all other PAX keys are rejected. This narrow subset does not establish compatibility with the PAX headers observed in the historical image. Nonempty directory replacement is rejected. Link handling deliberately accepts only a subset of OCI-valid images. The virtual root begins with synthetic mode/owner values and an unknown mtime; root attributes cannot be inferred when the image does not explicitly contain a root entry. The mtime of a directory whose children are changed or whiteouted in a layer becomes unknown, even if that layer also contains a directory header: runtimes can differ in whether and when they restore directory attributes. Unknown is represented as `None` and must never be treated as a verified timestamp. This model does not claim exact parity with a runtime's metadata. No host-path consumer may materialize or follow stored targets: they have not been resolved against the eventual image filesystem, and some may escape a host extraction root. A future consumer that follows links requires independently reviewed image-root confinement. The actual historical target was not retained, so this change does not establish its compatibility.

The parser independently checks complete uncompressed tar framing, requires a clean end and rejects malformed or concatenated archives. Whiteout markers must be empty regular files and operate only on lower-layer entries. Opaque and explicit whiteouts run before every same-layer addition, independent of archive ordering, consistent with the [OCI layer changeset specification](https://github.com/opencontainers/image-spec/blob/main/layer.md). Ambiguous cases, including whiteouts whose parent directory does not already exist in the lower tree, are rejected rather than guessed. A layer is staged and applied to a copy; failure never commits part of that layer.

Limits are intentionally small enough for synthetic testing: 128 MiB uncompressed bytes per layer; 32 MiB per regular file; 256 MiB aggregate virtual file bytes, counting hardlink aliases separately; 100,000 entries; 16 MiB cumulative path and link-target bytes during staging and path plus retained symlink-target bytes in the tree; 4,096 bytes per path; and at most 10 million tree-scan operations. The implementation may temporarily hold multiple copies of a layer and has Python object/JSON overhead beyond these limits. A 900-second monotonic deadline is checked between chunks and entries; it cannot interrupt blocked OS I/O or a long individual library call. It rejects images that exceed any bound. Actual runtime filesystem compatibility, full image resource use, Unicode/path semantics beyond the supported subset, and differential results against a reviewed OCI implementation have not been established.

Local synthetic fixtures cover explicit and opaque whiteouts, order independence, path traversal, duplicate entries, unsupported tar formats, hardlink replacement, symlink ancestry, malformed framing, byte/entry/work limits, deadlines and matching/tampered byte-bound manifests. These tests do not establish that the tree is complete or usable for release coverage, nor that it matches either real native LyraShield image. The byte verifier's independent authentication and input limits still apply. No publication or promotion workflow invokes this experiment; the unconditional hold remains in place.
