# Offline image layer byte-binding prototype

`scripts/verify_oci_layer_binding.py` is an **unwired, experimental offline check**, not a release qualification. Given a caller-supplied native manifest digest, expected platform, and a local directory whose direct child files are named by lowercase SHA-256 hex, it verifies the raw manifest bytes against that digest; parses a bounded, duplicate-key-free UTF-8 JSON manifest; verifies the configuration descriptor and bytes; checks Linux architecture and ordered `rootfs.diff_ids`; and streams each ordered layer while checking descriptor size, SHA-256 and the SHA-256 of its uncompressed bytes. It prints a report only after all checks succeed. The caller must use the process exit status and must never accept an old report after a failure.

The [OCI configuration](https://github.com/opencontainers/image-spec/blob/main/config.md) defines a DiffID as the digest of the uncompressed tar stream. The [manifest](https://github.com/opencontainers/image-spec/blob/main/manifest.md) binds the config and layer descriptors in application order. The supported subset is OCI image manifests with OCI config and plain or gzip layers, and Docker schema-2 image manifests with Docker config and gzip layers. It rejects foreign, nondistributable, zstd, inline and external-URL descriptors, unsupported platforms/variants, invalid sizes/digests, non-regular blobs, final-component symlinks, duplicate JSON keys, truncated or concatenated gzip, and trailing gzip data. This may reject valid image formats. It requires POSIX `O_DIRECTORY`, `O_NOFOLLOW`, and alarm signals; other platforms are unsupported.

Input limits: 1 MiB manifest, 16 MiB config, 128 layers, 16 GiB per compressed or uncompressed layer, and 64 GiB each for total compressed and total uncompressed layers; processing is limited to 900 seconds with an interruptible POSIX alarm. Individual reads and decompression output are bounded to 1 MiB, but JSON parsing has additional memory overhead, and OS I/O that cannot be interrupted by a signal can exceed the deadline. The code does not fetch or mutate image data. It opens blobs by a directory file descriptor without following final symlinks, and hashes the same stream it reads. A report binds those bytes at read time; it does not prevent subsequent file replacement. Consumers must use only a fresh, validated run and preserve trusted artifacts themselves.

A successful result **does not authenticate** the manifest or establish that it belongs to an independently qualified image/index, approved workflow or platform attestation. It does not parse tar contents, verify image-layer semantics or reconstruct a merged root filesystem; it does not inspect whiteouts, paths, file types, links or package metadata, compare the SPDX, or establish completeness. In particular a checksum-matching non-tar byte stream can pass this narrow check. The expected manifest digest and platform must eventually come from independently verified qualification, not from these caller-controlled blobs. A later reviewed qualification must bind the verified layers to the exact filesystem seen by all relevant package-coverage checks and to the signed SPDX artifacts. Runtime export would require its own trusted, isolated and validated bridge.

The local tests use generated tar/gzip and Docker/OCI descriptors, malicious edits and resource-limit fixtures. They do not establish support for actual LyraShield image manifests/layers, Linux execution, large-image throughput, OCI layer reconstruction, signatures or hosted qualification. The existing unconditional promotion hold remains in place; this script is not invoked by the publisher or consumer.
