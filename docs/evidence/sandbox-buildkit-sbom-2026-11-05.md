Each BuildKit manifest is referenced by the signed index, carries a subject descriptor and annotation referring to the corresponding native digest, and contains the referenced in-toto SPDX blob. Each fetched SPDX blob matched its descriptor size and digest and named the same native digest and platform in its in-toto subject. Both documents declare SPDX 2.3, Syft `v1.51.0` and BuildKit `v0.34.2`. The [upstream comparison](https://github.com/anchore/syft/compare/30fe53e629d0b368cf0c5ff79ac9387c19b12f79...v1.51.0) shows the fix for the scalar npm contributor issue is an ancestor of Syft 1.51.0; this is not a direct test of the historical binary or a proof of package completeness. Per-platform BuildKit provenance blobs were also fetched and hash-checked; each in-toto subject named its corresponding native digest.

`scripts/inspect_buildkit_sbom.py` independently checks the supported index → attestation manifest → SPDX blob byte/size chain and statement subject for one architecture. It rejects unsupported platform qualifiers and malformed or duplicate package identities; a missing optional package version remains permitted. Package text cannot contain control characters, and download locations are limited to SPDX sentinels and a conservative ASCII URI subset with checked authority, escapes and network schemes used by the observed documents; the tool never fetches them. This is not a general-purpose URI validator. These bounded syntactic checks do not establish that a package exists in the image or that all packages are present. Its expected index digest is supplied by the caller: it **does not verify a signature**, select a trusted workflow, validate run/attempt claims, verify the native filesystem, check package completeness, or implement the current consumer's signed SBOM-predicate policy. Its report explicitly says `index_bound_buildkit_sbom_inspection_only`; a successful report is not release qualification. It accepts at most 64 MiB per SPDX statement and parses JSON in memory; duplicate keys, unsupported formats and ambiguous descriptors fail closed. It was run locally on the exact two retained BuildKit SPDX blobs above and on malicious synthetic cases.

The GHCR referrer listing at the time of this check returned the signed index provenance and qualification bundles, not the new `sandbox-sbom/v1` binding expected by the current producer and consumer. The two BuildKit SPDX documents are different from the earlier 53,616,371-byte combined-index job artifact. Their cryptographic inclusion in the historical signed index is useful evidence but does not establish actual package completeness, current-policy acceptance, successful publication, or a promoted release. The historical run remains failed and the unconditional promotion hold remains in place.
