# Offline one-layer streaming integrity prototype

`scripts/verify_oci_layer_stream.py` reads a single compressed or plain layer from standard input without saving it. The caller provides its expected SHA-256 descriptor digest, byte size, media type and uncompressed DiffID. The verifier checks the compressed bytes and size, streams decompression in chunks, checks the uncompressed SHA-256, measures the uncompressed length and enforces its cap. It does not compare that length with an independently supplied expected size. It emits `single_layer_integrity_only` JSON only after the entire input reaches EOF and passes. OCI plain tar and gzip, and Docker gzip, are supported. Multi-member gzip, trailing data, unsupported compression, malformed sizes or digests, truncation, corruption, and cap violations fail closed.

This is an **unwired prototype**, not image or release qualification. The caller must independently authenticate the image index, native manifest, config and ordered descriptor/DiffID pair before supplying them, and check both the fetcher's and verifier's exit statuses. A successful report by itself does not prove where a stream came from, that the source process succeeded, that the bytes are a valid tar or OCI changeset, that other layers verified, that a root filesystem can be reconstructed, or that any SBOM is complete. Consumers must use fresh outputs and never accept a stale report after an error. The existing promotion hold remains in place.

Input and decompression chunks are capped at 1 MiB, each compressed and uncompressed layer at 16 GiB, and the CLI uses a 900-second POSIX alarm. OS I/O that cannot be interrupted by a signal remains outside that deadline. Gzip codec, Python and process overhead add memory beyond the chunk cap. The existing local-file verifier shares this streaming code; callback data used by the virtual reconstructor is provisional until the complete layer's descriptor and DiffID pass. This prototype does not retain layer bytes and cannot feed the current in-memory reconstructor without separately obtaining and buffering those bytes.
