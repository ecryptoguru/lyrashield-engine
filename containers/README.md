# Reviewed sandbox dependency exceptions

The sandbox installs the complete hash-pinned `python-requirements.txt` with
`--no-deps`, applies exact reviewed metadata exceptions, then requires `pip check`.
Dependency audits remain mandatory. Neither upstream tool's Python source is
modified. The patch validates the pinned distribution, the exact original
dependency field, and the original METADATA checksum/size in RECORD before any
write, then updates RECORD to describe the changed bytes.

- Dirsearch 0.5.0: the existing exception permits the tested PyOpenSSL 26.4.0.
- Semgrep 1.178.0: permit only `pyjwt[crypto]>=2.15.1,<2.16.0`, replacing its
  vulnerable `~=2.13.0` restriction. Keep Semgrep's original verified wheel and
  hashes. PyJWT 2.15.1 is pinned in both engine and sandbox locks (CVE-2026-101918
  fix line); the verified Semgrep wheel and its source remain unchanged.
- Semgrep 1.178.0 runtime: MCP 1.30.0 fixes redirect/header and schema-reference
  issues. OpenTelemetry API/SDK/exporter 1.45.1 and matching instrumentation
  0.66b1 fix the vulnerable API line. These exact resolver overrides correspond
  to exact METADATA substitutions, validated together before writes.
- Independent security refresh: aiohttp 3.14.5, graphql-core 3.3.1, certifi
  2026.10.19, and setuptools 84.1.0. The graph is hash-pinned for both CPUs.

The Semgrep exception requires the real installed MCP verifier to accept a
valid RS256 token and reject forged/expired tokens and redirected JWKS. The
sandbox smoke script also verifies the unchanged CLI version and a real local
finding. `verify_semgrep_pyjwt.py` runs these checks without credentials or
provider traffic. A JWKS redirect raises a PyJWKClient error and does not accept
a token or contact the redirected destination.

To reproduce the sandbox graph independently from the engine SDK constraints:

```sh
uv --no-config pip compile containers/requirements.in --generate-hashes --universal \
  --no-header --no-annotate \
  --overrides containers/pyjwt-override.txt \
  --output-file containers/python-requirements.txt
```

Preserve the hash-lock's explanatory header and inspect the resulting diff;
only the explicitly reviewed security graph should change. The resolver exception
is explicit and limited to that dependency; the post-patch `pip check` must
still enforce every installed dependency.

The compatibility script also proves real requests/threading instrumentation,
parent context propagation, and a successful OTLP HTTP export to a loopback
fixture. The unchanged Semgrep CLI must produce exactly one expected JSON finding.
No provider credentials or external telemetry are used.

Remove the Semgrep exceptions only after an official release declares a fixed
PyJWT range and passes the same checks. Until then, rollback requires a tested
image retaining patched PyJWT. Do not restore vulnerable PyJWT or suppress an
audit to make the upstream restriction pass. If the compatibility checks fail,
keep release blocked for a reviewed alternative.

Brotli CVE-2026-111497: the signed Kali snapshot still serves `1.2.0-4+b1`
on amd64 and arm64. `install_brotli.sh` authenticates both Debian
`libbrotli1=1.2.0-4.1` and `python3-brotli=1.2.0-4.1` before installing either.
The Python extension statically includes its decoder. Both packages are applied
after the final APT install. Smoke verifies both runtime ELF hashes, binary/source
versions, and real shared-library/system-Python decodes. No Debian repository is added.

The application pip 26.2.2 exception replaces its urllib3 and msgpack vendors
with the fixed hash-locked upstream sources. `pip_vendor_wheels.json` binds the
complete installed payloads to independently pinned official wheel inventories,
including modules, licenses and portable resources. Its own SHA256 is anchored
in the helper. Refresh those inventories from authenticated wheel archive bytes,
never from the installed RECORD being checked. Every expected entry and the
complete package file set must match; only explicit installer metadata, qualified
entrypoint templates, and generated bytecode vary. Bytecode is discarded after
all validation and regenerated from admitted source. Both targets, resources,
write destinations and the new RECORD are checked before mutation. The Emscripten
worker JS is retained and verified; native ABI extensions are not vendored.

Retire 6.1.0 has a narrow downstream TLS amendment after the exact npm hash-lock
installation. `patch_retire_tls.cjs` verifies its original HTTP-client SHA256 and
sets the requested target host on the CONNECT TLS socket. IP targets still omit
SNI, while default certificate verification checks the requested IP. HTTP/HTTPS
proxy authentication and explicit insecure mode remain supported. The real
repository loader tests valid and wrong DNS/IP identities and requires zero
origin HTTP requests before rejection of a wrong identity.

The emSign G3 trust repair validates every PEM block in the actual active lookup
files and effective concatenated CAfile. A complete parsed-certificate count is
required; truncated, malformed, unreadable or missing trust inputs fail closed.
Only the fingerprint-identified packaged G3 source is disabled. Other anchors,
including the sandbox testing CA, remain trusted. The pip smoke independently
requires a readable, parseable effective CA bundle before writing a passing receipt.

CA source DER is parsed and roundtripped with the existing pinned X.509 parser;
the actual TLS context's canonical loaded fingerprints are checked independently.
Raw PEM payload hashes alone cannot attest root absence. The installer also
requires the current versioned pip launcher and its canonical hashed RECORD row,
admitted source and mode0755. Existing multiply linked mutation targets are
rejected before any writes, preserving files outside the environment.

## Go tool security rebuilds

The eight Go executables are rebuilt from the same application revisions in
`go-tools/sources.tsv`. Every source archive is SHA256-verified before extraction.
The builder uses the official Go 1.27.3 Linux archive, independently SHA256-pinned
for amd64 and arm64, with `GOTOOLCHAIN=local`. The compiler and module caches stay
in the builder stage. Official compiler provenance: [Go downloads](https://go.dev/dl/)
and [release security fixes](https://go.dev/doc/devel/release#go1.27.3).

Each tool has a complete reviewed `go.mod`/`go.sum` pair overlaid on its immutable
upstream source. `go mod download`, `go mod verify`, `go build -mod=readonly` and
an unchanged-lock checksum check enforce the resolved graph. Go's public checksum
database remains enabled; no module checksum exclusions or audit ignores are
introduced. Preserve upstream replacements when refreshing these graphs. The
security changes are limited to the affected dependency graph:

- Where already present, x/net 0.62.0 (including its required crypto 0.58.0,
  text 0.43.0 and system dependencies), and compress 1.18.7. Gitleaks has no
  x/net dependency added merely to match the other tools.
- Gospider: xmlquery 1.3.1, xpath 1.3.6, logrus 1.8.3 and protobuf 1.33.0.
- Katana: pgx 5.12.0, covering the reported critical protocol-decoding issues and
  the later authentication/batch fixes; see the
  [upstream changelog](https://github.com/jackc/pgx/blob/v5.12.0/CHANGELOG.md).
- Vulnx: jsonparser 1.1.2.
- Gitleaks: rardecode 2.2.1 and xz 0.5.15, retaining the original archives
  0.1.2 adapter and the upstream `gore2regex`
  release tag and 8.30.1 version identifier.
- Trivy: containerd 2.3.6, go-git 5.19.2, go-jose 4.1.6, grpc 1.83.2,
  oras-go 2.6.2, moby/sys/user 0.4.1 and OpenTelemetry 1.45.0. Keep its upstream
  `jsonv2` experiment, static build, and 0.73.0 version identifier.
- TruffleHog: go-jose 4.1.6, grpc 1.83.2, edwards25519 1.1.1,
  amqp091-go 1.14.0 and OpenTelemetry SDK 1.45.0. Preserve its source replacements
  and 3.99.2 version identifier. The binary is deliberately unpacked: upstream
  UPX packaging hides build metadata from ordinary image scans. Source rebuilding
  preserves the scanner-visible Go module metadata.

The image retains upstream LICENSE/NOTICE files and each tool's source URL/SHA,
resolved module locks, compatibility patch and binary build metadata under
`/usr/local/share/lyrashield/go-tools/`, including the Go license/patent notices.

`verify_go_tools.py` checks CLI compatibility, crawls a loopback HTML fixture
using httpx/Katana/Gospider, and detects a synthetic GitHub token using
Gitleaks/TruffleHog/Trivy. It also checks a benign Gitleaks fixture and a secret
inside gzip/tar, Zstandard and XZ inputs. These run in
both sandbox smoke gates without credentials or external target traffic;
TruffleHog verification/updates and Trivy database downloads are disabled.
Compilation and local fixtures are compatibility evidence, separate from the
mandatory final image audit. Preserve raw advisory rows when a package has no
fixed version; package names alone do not prove reachable vulnerable symbols.

Gospider's original publicsuffix call accepted IPv4 targets indirectly. Fixed
x/net 0.62.0 rejects IP literals, so `gospider/source.patch` explicitly recognizes
IP targets before the domain lookup. It changes no domain-target scope behavior.
The patch applies only to the archive-verified original source with zero fuzz;
the direct loopback crawl fixture proves the preserved behavior.

Trivy's `source.patch` replaces the removed experimental `json.SkipFunc` with
Go1.27's documented `errors.ErrUnsupported` when no decoder input was consumed.
This preserves its location-tracking fallback behavior while using the fixed
compiler. Both skip sites are patched (location tracking and CloudFormation parameter
fallback). A dedicated upstream-package regression checks that string, boolean,
null, array and object fallbacks leave the next decoder value untouched.
The upstream JSON helper tests and local JSON scanner output remain
required compatibility checks. See [Go1.27 JSON unmarshaler semantics](https://pkg.go.dev/encoding/json/v2@go1.27.3#UnmarshalerFrom).

Trivy's module Go directive is raised to 1.27.0 to match its patched JSON API
contract; the exact compiler remains 1.27.3. The source package tests keep Go
vet enabled and verify fallback input preservation.

Independent govulncheck adds Goldmark 1.7.17 (GO-2026-5320/CVE-2026-5160)
where already imported. `verify_goldmark.go` checks escaped links, autolinks,
images and a benign HTTPS link against each actual selected graph during the
build. The old 1.7.13 renderer fails the same regression. See
https://pkg.go.dev/vuln/GO-2026-5320 and the upstream fixed renderer.
