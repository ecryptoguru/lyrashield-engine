# Rebuilt Kali Go packages

The runtime installs locally rebuilt ffuf, Naabu, Nuclei and subfinder packages at their original `/usr/bin` paths. Their package versions append `+lyra1` to the original distro revision. The package retains the original files, documentation and notices, with a new binary, package checksums and a provenance directory under `/usr/share/doc/<name>/lyrashield-build/`.

## Source identity

`sources.tsv` pins the .dsc, upstream archive, Debian packaging overlay and original binary package for each supported architecture. The hashes were verified against the Kali snapshot's signed Sources and amd64/arm64 Packages indexes. The InRelease SHA-256 was `62375e475a01fed422730632651d784cc42c4145223313178c8519f9822eefc6`, signed by `827C8569F2518CC677FECA1AED65462EC8D5E4C5` using the repository's pinned Kali keyring. Builds check each downloaded payload, apply the package's quilt series, then apply the reviewed local changes. A mirror losing a pinned archive stops the build. [Kali archive](https://kali.download/kali/dists/kali-last-snapshot/InRelease)

Use the builder's pinned Go 1.27.3, native architecture, gcc and the signed snapshot. ffuf retains the actual Debian dependency versions for goquery, pencode, xdg, brotli, cascadia and go-toml. pencode uses the commit underlying the signed 0.4 source, upstream tag v0.4. Nuclei retains its Kali disabled engine update and default template path. Naabu, subfinder and ffuf retain CGO, while Nuclei retains its PGO/static build. Naabu requires the libpcap shared library at runtime because its Go pcap wrapper dynamically loads the library. The build records the replacement module graph, build information, source manifest, toolchain license, available top-level third-party module notices and binary hash alongside the packaged copyright file.

ffuf's original Go 1.26 Debian binary offered sixteen TLS 1.0–1.2 cipher suites and three TLS 1.3 suites. Go 1.27 dropped six formerly offered RSA/3DES suites and its old compatibility switches. The ffuf-only patch restores its observed outbound target-scanning cipher list. TLS 1.3 remains managed by Go. No other TLS client or system policy uses this setting. The installed fixture serves TLS 1.2 RSA AES128-SHA on loopback and requires an HTTP match. The corrected ClientHello matched all 19 original cipher IDs in order. Go 1.27 still omits the former SHA-1 RSA/ECDSA signature schemes (0x0201/0x0203) and adds post-quantum groups and signatures. Peers requiring SHA-1 handshake signatures are outside the reproduced profile. The available SHA-1 switch would affect every TLS client in the process.

## Dependency qualification

Nuclei's old go-github/v30 links the unmaintained golang.org/x/crypto/openpgp commit signer. A replacement scoped to the Nuclei graph points the v30 import path to v51.0.0, which uses ProtonMail’s implementation. This covers both the application’s repository lookup and issue reporting clients and the transitive projectdiscovery/utils/update client. The lock retains the published v51 module checksum. [Go advisory](https://pkg.go.dev/vuln/GO-2026-5932) · [SDK implementation](https://github.com/google/go-github/blob/2317ed881692a63a67cf60961fe8ffe2f16217b0/github/git_commits.go)

The four primary modules are versioned in `applications.cdx.json` because Go marks local builds as devel. Scan this source-version supplement separately from each extracted installed ELF. The upstream Git revisions in it were compared file-by-file with the authenticated orig archives. Per-architecture binary hashes are in each package’s provenance.

Inspect the final extracted executables as well as package ownership. Trivy may skip Go applications owned by APT, and its Kali OS package coverage does not establish binary patch status. Keep the raw scanner results, independently check Go advisory package/symbol scope, and execute the installed loopback fixtures. Repeat for Linux amd64 and arm64 when updating these inputs.

The eight existing tools and these four packages share the pinned toolchain and one temporary compiler/module cache. The combined build removes that cache in the same Dockerfile layer. BuildKit mounts the local .debs read-only after the final documentation purge. The four-package dpkg invocation includes every archive path, including when base image defaults exclude documentation. The image checks package integrity immediately after installation. The release uses `verify_distro_go_tools.py --receipts-only` to bind the binary, module locks and source descriptor to the corresponding application component.
